# Test Plan — Yandex Disk REST API

## Цель

Проверить основные операции REST API Яндекс.Диска для работы с папками и автоматизировать основные позитивные и негативные сценарии.

## Стек

- Python 3
- Pytest
- requests

## Проверяемые методы

- PUT — создание папки
- GET — получение информации о ресурсе
- POST — копирование ресурса
- DELETE — удаление ресурса

## Тестовые сценарии

### PUT /v1/disk/resources

- PUT-01: создание папки с валидным path
- PUT-02: запрос без обязательного path
- PUT-03: создание уже существующей папки
- PUT-04: создание папки в несуществующем родительском каталоге

### GET /v1/disk/resources

- GET-01: получение существующей папки
- GET-02: получение ресурса с параметром fields
- GET-03: запрос без path
- GET-04: получение несуществующего ресурса
- GET-05: запрос без OAuth-токена

### POST /v1/disk/resources/copy

- POST-01: копирование существующей папки
- POST-02: асинхронное копирование с force_async=true
- POST-03: запрос без from
- POST-04: запрос без path
- POST-05: копирование несуществующего ресурса
- POST-06: копирование в уже существующий path без overwrite
- POST-07: копирование с overwrite=true
- POST-08: запрос без OAuth-токена

### DELETE /v1/disk/resources

- DELETE-01: удаление существующей папки
- DELETE-02: проверка перемещения ресурса в Корзину
- DELETE-03: удаление с permanently=true
- DELETE-04: удаление несуществующего ресурса
- DELETE-05: запрос без path
- DELETE-06: запрос без OAuth-токена
- DELETE-07: асинхронное удаление с force_async=true

## Дополнительные сценарии

- полный жизненный цикл: создать → получить → скопировать → удалить
- удаление → Корзина → восстановление
- проверка завершения асинхронной операции

## Вне текущего scope

Не воспроизводятся специально ошибки, зависящие от тарифа, состояния сервиса или ограничений инфраструктуры: 403, 406, 412, 413, 423, 429, 503 и другие подобные случаи.
